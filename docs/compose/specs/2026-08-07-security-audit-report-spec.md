## 2. 機能仕様

### 2.1 ファイル構成と内容

`セキュリティ監査レポート.md`（ルート直下）は以下の節を含む Markdown 文書:

1. ヘッダ（監査日・対象・方法・詳細版へのリンク）
2. 総評 — クリティカル/高危険度なし・F1〜F4 はすべて修正済みである旨
3. 監査方法 — 静的レビュー + 動的テスト（稼働中コンテナへの許可済み侵入テスト）+ ランタイム検査
4. テスト結果サマリ（実測）— 表形式で 10 項目（SQLi / パラメータ注入 / 機密ファイル / DB直アクセス / トラバーサル / メソッド乱用 / ブルートフォース / セッションフィクセーション / 情報開示 / ヘッダ）
5. 発見と対応（F1〜F4・すべて修正済み）— 指摘内容・影響・対応・検証実測を表形式で
6. 検証済みの防御 — SQLi / XSS / 認証 / CSRF / DBファイル保護の5項目
7. 修正後の再検証 — 4 スイート（12/12・14/14・17/17・17/17）と証跡ファイル名
8. 監査時の注意事項（設計上許容・変更不要）
9. 結論
