## Q1. 実行環境（どこで・どのように使うか）

- **質問**: このアプリはどこで・どのように使いますか？（データの保存方法に直結します）
- **Why asked**: 「簡単なアプリ」という漠然とした依頼に対し、データの保存先（端末内 vs サーバー）を決める最重要の決定。保存方式がアーキテクチャ全体を左右する。
- **Background**: 当初は単一HTML + localStorage のスタンドアロン構成を想定していた（最小構成のため）。
- **Result**: 最初の回答は「スマホで使用」。しかし Q5 でユーザーが「webサーバーとwebアプリとする。各端末には何も保存しない。sqlite」と回答し、サーバー型に上書き確定。→ サーバー側SQLiteに集約保存。

## Q2. 枚数の入力方法（操作感の核）

- **質問**: 駐車券を渡すとき、枚数をどう入力しますか？
- **Why asked**: 操作感の核。+1ボタン型と数字入力型でUI設計が大きく変わる。
- **Background**: カウンター業務での素早い記録を想定し、+1ボタン型を推奨候補としていた。
- **Result**: 「枚数を数字入力して登録」— 1回の操作で複数枚（例: 3枚）をまとめて登録できる形式を採用。

## Q3. 日時の記録方法

- **質問**: 日時はどのように記録しますか？
- **Why asked**: データモデルに直結（自動記録 vs 手動指定）。手動だと過去分の入力UIが必要になる。
- **Background**: 実務では「渡した瞬間」を記録するのが目的のため、自動が自然。
- **Result**: 「記録した瞬間の現在日時を自動記録」を採用。手入力なし。

## Q4. 必要な機能（複数選択）

- **質問**: 記録した後の確認・機能で必要なものはどれですか？
- **Why asked**: YAGNIの原則に従い、スコープを確定するため。何が本当に必要かを確認した。
- **Background**: 「簡単なアプリ」の範囲と、実務上必要な確認機能のバランスを探った。
- **Result**: すべて採用 — 今日の記録一覧 / 今日の合計枚数 / 日別の合計（過去の集計）/ 誤操作の取り消し（削除）。

## Q5. データの書き出し（アーキテクチャ転換点）

- **質問**: スマホのブラウザ内だけにデータを保存すると、キャッシュ削除や機種変更でデータが消えるリスクがあります。データの書き出し（バックアップ/報告用）機能は必要ですか？
- **Why asked**: 端末内保存の最大の弱点（データ喪失）を指摘し、バックアップ手段の要否を確認。
- **Background**: この質問まで端末内保存(localStorage)を前提としていた。
- **Result**: 「webサーバーとwebアプリとする。各端末には何も保存しない。sqlite」— アーキテクチャをサーバー型に変更。端末にデータを残さない設計が確定。CSV書き出しは要件から外れた（サーバーに永続化されるため）。

## Q6. 日別集計の表示範囲

- **Why asked**: 集計UIの表示範囲（期間セレクタ）を決めるため。
- **Background**: 直近1週間/1ヶ月/全記録の選択肢を提示していた。

## Q7. 技術スタック

- **質問**: Webサーバーの技術スタックはどれにしますか？（このマシンには Node v26 / Python 3.12 が入っています）
- **Why asked**: 実行環境の制約（このマシンにはPHPが無い）と、ユーザーの運用先の前提を確認するため。
- **Background**: Node.js組み込みSQLite（依存ゼロ）を推奨候補としていたが、ユーザーが運用先を重視。
- **Result**: 「出来る限り汎用的なレンタルサーバーで動くように、phpアプリとする」— PHP + SQLite(PDO) で実装。日本の一般的なPHP対応レンタルサーバー（Xserver系など）で動作することを目標とする。ローカルテスト用に PHP 8.3 CLI + pdo_sqlite をインストール（このマシンで動作確認済み）。

## Q13. DockerデプロイのDB永続化（要件ロック後の追加指示）

- **質問**: Dockerコンテナは破棄可能な存在です。データベース（data/parking.db）はどこに置きますか？
- **Why asked**: コンテナのボリューム設計を誤ると、コンテナ再作成で全記録が消失するため。永続化の場所（ホスト vs コンテナ内）は最も影響の大きい決定。
- **Background**: 「サーバーが立ち上がってない。dockerでサーバー立ち上げて」の指示で Docker デプロイが必要に。アプリ実装・検証は完了済み（PHP + PDO SQLite）。このマシンは WSL2 + Docker Desktop（ポート公開は Windows 側 localhost へ自動転送）。なお現行の php -S 運用には「GET /data/parking.db が 200 で全データを返す（.htaccess が php -S では無効）」という実証済みの穴があった。
- **Result**: **ホストに永続化（バインドマウント）**。ホストの `./data` をコンテナの `/var/www/html/data` にマウントし、コンテナを再作成してもデータは残る。バックアップは従来どおり data/parking.db のファイル管理。コンテナ内の Apache(www-data) が書き込むため、起動時にエントリポイントで所有権を www-data に調整する。

## Q14. Dockerコンテナの自動起動・自動復帰（要件ロック後の追加指示）

- **質問**: 「サーバーが立ち上がってない」という事象が再発しないよう、コンテナの起動方針はどうしますか？
- **Why asked**: 直前に「サーバーが立ち上がってない」と報告があったため、docker 化に際し再発防止の方針を確定する必要があった。docker ならプロセスライフサイクルをシェルから切り離せる。
- **Background**: 従来は `php -S` をシェルのバックグラウンドで起動しており、セッション終了でプロセスが消える（あるいは到達性の問題が起きる）運用だった。
- **Result**: **自動起動・自動復帰（restart: unless-stopped）**。docker デーモン起動時にコンテナが自動起動し、クラッシュ時は自動再起動。明示的に停止しない限り常時稼働する。

## Q15. Dockerコンテナ内の実行方式（要件ロック後の追加指示）

- **質問**: コンテナ内の実行方式は？（現状の php -S 運用には「data/parking.db が直接ダウンロード可能」という実証済みの穴があり、サーバー方式で挙動が変わります）
- **Why asked**: ベースイメージ（Apache vs CLI+php -S）でデータ保護の挙動が変わるため。Apache なら既存の data/.htaccess（deny-all）が機能して DB 直アクセスを遮断できる。
- **Background**: 実証済み: `curl http://127.0.0.1:4500/data/parking.db` → 200（16KB 全データ）。`data/.htaccess` は Apache ディレクティブであり php -S では無効。アプリは汎用レンタルサーバー（Xserver系 = Apache + PHP）での動作を目標としている。
- **Result**: **Apache 版 `php:8.3-apache` を採用**。data/.htaccess（deny-all）がそのまま機能し、DB直ダウンロードの穴を塞ぐ。ポートは `4500 → コンテナ80` にマッピング（ブラウザからは従来どおり `http://<host>:4500/`）。php:8.3-apache に pdo_sqlite 拡張を追加してビルド。

## 確定要件サマリ

1. PHP + SQLite(PDO) のWebアプリ。できる限り汎用的なレンタルサーバーで動作。
2. 端末にはデータを保存しない。サーバー側SQLiteに永続化。
3. サーバーはポート4500で稼働（LAN内利用、ログインなしの共有）。
4. 枚数は数字入力（1回で複数枚登録可）。日時は記録時に自動記録（Asia/Tokyo）。
5. 機能: 今日の合計枚数 / 今日の記録一覧 / 日別の合計（年・月指定）/ 記録の削除。
6. PW(1234、設定ファイル固定)で保護: 削除操作と日別集計。記録・今日の合計・今日の一覧はPWなし。
7. モバイルファーストの日本語UI。
8. CSSフレームワーク: Bootstrap 5.3.3（CDN版・jsDelivr）。
9. Dockerデプロイ: ホストの ./data をバインドマウントしてDB永続化（Q13）。
10. Dockerコンテナは自動起動・自動復帰（restart: unless-stopped）（Q14）。
11. Docker ベースイメージは php:8.3-apache。data/.htaccess により DB直ダウンロードを遮断（Q15）。
