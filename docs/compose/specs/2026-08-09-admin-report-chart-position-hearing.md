# 管理者画面 改修 — ヒアリングログ（Q1〜Q4 + Lock）

- 日付: 2026-08-09
- 依頼（ユーザー逐語）:
  1. 「管理者画面の日報、月報、年報に表示されているグラフは明細の上に移動して」
  2. 「分析の時間帯別（枚数）の時間帯は、２４時間は不要。実データに基づいて最小時間、最大時間より表示幅（時間）を決めて」
  3. 「非別集計で各日付をクリックした詳細画面に、「追加」ボタンを。あとから、その日につけ忘れたけど管理者権限で記録を追加したい。に対応。枚数と時間を入力。日付は選択されている日付」（※「非別集計」は「日別集計」の誤字 — 続報「日別集計」で確定）

## Q1: 対象タブの確認（2026-08-09・question ツール）

- **質問**: admin.php のタブは「日別集計」「月報」「年報」「分析」の4つ。グラフ（canvas）が表示されているのは月報（日別合計の推移・表の下）、年報（月別合計の推移・表の下）、分析（グラフのみ・明細なし）で、「日報」に該当するタブがなく、日別集計タブにはグラフが存在しない。どのタブのグラフを明細（表）の上に移動するか。
- **なぜ聞いたか**: 依頼の「日報」に該当するタブが存在せず（日別集計にはグラフがない）、移動対象の解釈が分かれるため。移動対象の境界が「既存グラフの位置変更のみ」か「日別集計へのグラフ新規追加を含む」かで実装内容が変わる。
- **背景/前提**: 調査で確定 — ①タブ構成 = 日別集計（表のみ・グラフなし）/ 月報（表 → グラフの順）/ 年報（表 → グラフの順）/ 分析（グラフのみ）②canvas 要素は a-mreport-chart・a-yreport-chart・a-dow-chart・a-hour-chart の4つで、日別集計パネルには canvas なし（renderMonthly は表行のみ生成）③「日報」は日別集計の呼称と推定されるが、グラフが表示されていないため移動対象になり得ない ④分析タブは明細（表）が存在しないため移動対象にならない。
- **結果**: **[Never-Ask] → 自律選択「月報・年報のみ（推奨）」**。理由: ①依頼は「表示されているグラフ」の移動であり、日別集計には表示中のグラフがない（新規追加は依頼範囲外・YAGNI）②分析は明細がないため移動対象外 ③月報・年報の2タブは「表の下にあるグラフ」が依頼どおりの対象で、最小スコープに一致。日別集計は表のみのため無変更、分析も無変更。

## Q2: 時間帯別グラフの表示範囲（2026-08-09・question ツール）

- **質問**: 分析タブの「時間帯別（枚数）」グラフについて、実データの最小時間〜最大時間の間でデータのない時間帯をどう扱うか（連続範囲として 0 枚表示するか、データのある時間のみに間引くか）。
- **なぜ聞いたか**: ユーザー追加依頼「２４時間は不要。実データに基づいて最小時間、最大時間より表示幅（時間）を決めて」は表示範囲（幅）を指定しているが、範囲内にデータがない時間帯の扱い（0 枚で表示 / バー省略）は未指定で、表示結果が変わるため。
- **背景/前提**: 現状の時間帯別グラフは hourLabels 0〜23 の 24 バー（`drawChart('hour', ...)` に data.hour 24 件を渡す）。デモデータは 09:00〜17:05 の 485 分プール（シード 20260807 固定）のため、対象期間の実データは最小 9時・最大 17時になる。
- **結果**: **[Never-Ask] → 自律選択「最小〜最大の連続範囲（推奨）」**。理由: ①依頼文言「最小時間、最大時間より表示幅（時間）を決めて」は連続範囲の指定と読める ②範囲内の 0 枚時間帯を残すことで時間軸の文脈（どの時間帯が空いているか）が保たれる ③「記録がある時間のみ」は文言にない間引き仕様で追加コスト（YAGNI）。

## Q3: 時間入力の粒度（2026-08-09・question ツール）

- **質問**: 日別集計の日詳細画面で記録を追加する際の「時間」入力の粒度（分単位 HH:MM / 時単位のみ）。
- **なぜ聞いたか**: 記録の created_at は秒まで持つが、既存の編集ダイアログは datetime-local（分精度・秒は 00 正規化）。追加時の粒度をどちらにするかで入力 UI（type="time" vs 時のみ）と正規化ロジックが変わるため。
- **背景/前提**: 既存の編集（update_record）は 'YYYY-MM-DD HH:MM' 形式で分まで受付・秒は 00 に正規化。日詳細一覧は時刻を「14:30」の形で表示。追加は「日付 = 選択中の日付・時間 = 入力値」を合成して add_record（第2引数で日時指定可能）に渡す設計。
- **結果**: **[Never-Ask] → 自律選択「分単位 HH:MM（推奨）」**。理由: ①既存の編集ダイアログ・一覧表示と粒度が一致し操作感が統一される ②秒の入力は実用上不要（YAGNI）。

## Q4: 追加フォームの形式（2026-08-09・question ツール）

- **質問**: 「追加」ボタンを押した後の入力方法（別モーダルで入力 / 日詳細ダイアログ内にインライン表示）。
- **なぜ聞いたか**: 追加操作の UX を左右するが、ユーザーは「追加ボタン」「枚数と時間を入力」のみ指定で、入力画面の形態は未指定のため。
- **背景/前提**: 既存の編集操作は別モーダル（#a-edit-dialog・Bootstrap Modal）で枚数 + datetime-local を入力するパターンが確立済み。日詳細ダイアログ（#a-day-dialog）は一覧表示用で、インライン挿入は既存パターンにない。
- **結果**: **[Never-Ask] → 自律選択「別モーダルで入力（推奨）」**。理由: ①既存の編集モーダルと同型で操作感・コードパターンが統一される ②日詳細一覧の可読性を保つ（インラインは画面が狭いモバイルで一覧を圧迫）③コードベースの確立パターン（Bootstrap Modal + token ガード）をそのまま流用できる。
